# Guía de contribución

## Ramas

No trabajar directamente sobre `main`. Cada integrante debe crear una rama desde `develop`:

```text
feature/nombre-de-la-funcion
fix/nombre-del-error
docs/nombre-del-documento
```

## Commits

Usar mensajes breves y claros:

```text
feat: agregar pantalla de mapa
fix: corregir permiso de ubicación
docs: actualizar requisitos
test: agregar prueba de filtros
```

## Pull Requests

Cada Pull Request debe indicar:

- Qué se modificó.
- Qué tarea de Monday corresponde.
- Cómo se comprobó el cambio.
- Capturas cuando exista un cambio visual.

Se recomienda que otro integrante revise el cambio antes de integrarlo en `develop`.
